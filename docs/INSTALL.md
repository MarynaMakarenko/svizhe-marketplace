# Встановлення та запуск

Інструкція розрахована на людину, яка вперше бачить проєкт. Усі команди виконуються в терміналі з каталогу проєкту.

## 1. Що потрібно

| | Мінімум |
|---|---|
| Операційна система | Linux, macOS або Windows з WSL2 |
| Docker | версія 24 або новіша, з Docker Compose v2 |
| Пам'ять | 1 ГБ вільної оперативної пам'яті |
| Диск | 2 ГБ |
| Мережа | вільний порт (типово 8088) |

Перевірити, що Docker встановлено:

```bash
docker --version
docker compose version
```

Нічого іншого (Node.js, PostgreSQL) встановлювати не потрібно — усе є в контейнерах.

## 2. Отримати код

```bash
git clone <адреса репозиторію> svizhe-marketplace
cd svizhe-marketplace
```

## 3. Налаштувати

```bash
cp .env.example .env
```

Відкрийте `.env` у будь-якому редакторі. Для пробного запуску на власному комп'ютері можна нічого не змінювати.
**Для сервера, доступного з інтернету, обов'язково змініть перші два значення:**

| Змінна | Що це | Типове значення |
|---|---|---|
| `POSTGRES_PASSWORD` | пароль бази даних | `change_me_please` — **змінити** |
| `JWT_SECRET` | секрет для підпису токенів входу; довгий випадковий рядок | **змінити** |
| `POSTGRES_DB`, `POSTGRES_USER` | назва бази та користувач | `svizhe` |
| `JWT_EXPIRES_IN` | скільки діє вхід користувача | `7d` |
| `SEED_ON_START` | заповнити порожню базу демо-даними | `true` |
| `WEB_PORT` | порт сайту | `8088` |

Згенерувати випадковий секрет:

```bash
openssl rand -hex 32
```

> Пароль бази задається лише під час першого запуску. Якщо змінити його пізніше, базу потрібно створити заново (розділ «Почати з чистої бази» в [посібнику адміністратора](ADMIN_GUIDE.md)).

## 4. Запустити

```bash
docker compose up -d --build
```

Перший запуск триває 2–4 хвилини (завантажуються образи та збирається інтерфейс). Наступні — кілька секунд.

Що відбувається автоматично:

1. стартує PostgreSQL;
2. системна частина чекає, поки база буде готова, і застосовує міграції (створює таблиці);
3. якщо база порожня і `SEED_ON_START=true` — додаються демо-дані;
4. стартує nginx з інтерфейсом.

## 5. Перевірити

```bash
docker compose ps
```

Усі три сервіси (`db`, `backend`, `frontend`) мають бути у стані `Up`, а `db` і `backend` — `healthy`.

```bash
curl http://localhost:8088/api/health
```

Очікувана відповідь: `{"status":"ok", ...}`.

Відкрийте в браузері <http://localhost:8088> і увійдіть під демо-акаунтом з [README](../README.md#демонстраційні-акаунти).

## 6. Запуск без демо-даних (для реальної роботи)

1. У `.env` поставте `SEED_ON_START=false` **до першого запуску**.
2. Запустіть: `docker compose up -d --build`.
3. Зареєструйте на сайті акаунт майбутнього адміністратора (як звичайного покупця).
4. Надайте йому роль адміністратора:

```bash
docker compose exec db psql -U svizhe -d svizhe -c "UPDATE users SET role = 'admin' WHERE email = 'ваш@email'"
```

5. Увійдіть під цим акаунтом і створіть категорії в розділі «Адмін-панель → Категорії».

## 7. Зупинити та запустити знову

```bash
docker compose stop      # зупинити; дані зберігаються
docker compose start     # запустити знову
docker compose down      # зупинити й видалити контейнери; дані зберігаються у томах
```

Контейнери мають політику `restart: unless-stopped`, тому після перезавантаження сервера сайт піднімається сам (якщо Docker запускається разом із системою).

## 8. Якщо щось не так

| Симптом | Причина та рішення |
|---|---|
| `port is already allocated` | Порт зайнятий іншою програмою. Змініть `WEB_PORT` у `.env` і повторіть `docker compose up -d`. |
| Сайт відкривається, але товари не завантажуються | Системна частина ще стартує або впала. `docker compose logs backend --tail 50`. |
| `backend` постійно перезапускається | Найчастіше — невірний пароль бази (змінили `.env` після першого запуску). Див. примітку в розділі 3. |
| `Cannot connect to the Docker daemon` | Docker не запущено. Запустіть Docker Desktop або `sudo systemctl start docker`. |

Більше — у [посібнику адміністратора системи](ADMIN_GUIDE.md#несправності).
